# Project Structure

## Monorepo Layout

Reliva uses a **bun workspaces** monorepo. Each platform lives in `apps/` as its own workspace.
The root holds workspace configuration, shared tooling, and documentation.

```
reliva/                         ← Monorepo root
  apps/
    web/                          ← Next.js app (@reliva/web)
    extension/                    ← Browser extension (@reliva/extension) — Phase 6
  docs/                           ← Documentation (this folder)
  package.json                    ← Workspace root — scripts delegate to apps/
  bun.lock                        ← Shared lockfile across all workspaces
  .gitignore
  .prettierrc
  .prettierignore
  AGENTS.md
  PLANNING.md
  .env.example
```

Workspaces are declared in the root `package.json`:
```json
{
  "workspaces": ["apps/*"]
}
```

Running `bun install` at the root installs all workspace dependencies.

## Adding a New App (e.g. Mobile — Phase 7)

When Capacitor is added in Phase 7:
```
apps/
  web/
  extension/
  mobile/               ← new: @reliva/mobile
    android/
    ios/
    capacitor.config.ts
    package.json
```

Run `bun install` at the root to pick up the new workspace.

## Vercel Deployment

Vercel needs to know where the Next.js app lives. In the **Vercel project settings**:
- Set **Root Directory** to `apps/web`

Vercel will then:
1. Run `bun install` at the monorepo root (installs all workspace deps)
2. Run `bun run build` inside `apps/web`
3. Deploy the `apps/web/.next` output

The `vercel.json` for cron jobs lives inside `apps/web/`.

## Key File Responsibilities

| File | Responsibility |
|---|---|
| `apps/web/lib/db.ts` | MongoDB connection singleton. Always call `getDb()`, never instantiate MongoClient directly. |
| `apps/web/lib/auth.ts` | Auth.js config + `validateCaller(request)` — accepts both session cookies and bearer tokens. |
| `apps/web/lib/totp.ts` | otplib wrappers: generate secret, generate QR URI, verify code. |
| `apps/web/lib/crypto.ts` | Web Crypto API: PBKDF2 key derivation, AES-GCM encrypt/decrypt. Client-side only. |
| `apps/web/lib/types.ts` | TypeScript interfaces for all MongoDB document shapes. |
| `apps/web/lib/validations.ts` | Zod schemas shared between API route handlers and client forms. |
| `apps/web/middleware.ts` | Edge middleware — redirects unauthenticated requests away from `(app)` routes. |
| `apps/web/vercel.json` | Vercel Cron Job: calls `/api/cron/notify` daily at 8am. |
| `package.json` (root) | Workspace root. Scripts delegate to `apps/web`. Prettier lives here. |
| `apps/server/cmd/main.go` | Go entry point. Loads config, connects MongoDB, registers routes, runs with graceful shutdown. |
| `apps/server/internal/config/config.go` | Reads all env vars; panics on missing required vars so misconfiguration fails fast. |
| `apps/server/internal/db/db.go` | MongoDB singleton — connect once, reuse across handlers. |
| `apps/server/internal/middleware/auth.go` | JWT validation. `RequireAuth` (access token), `RequirePending` (step-1 token), `RequireCron` (secret). |
| `apps/server/internal/handlers/auth.go` | Two-step login: password → pending JWT → TOTP → access JWT. Also TOTP setup and backup codes. |
| `apps/server/internal/routes/routes.go` | Single source of truth for all routes and which middleware protects each group. |

## Naming Conventions

| Item | Convention | Example |
|---|---|---|
| Files | kebab-case | `task-card.tsx` |
| React components | PascalCase | `TaskCard` |
| Functions / variables | camelCase | `getTaskById` |
| Package names | `@reliva/<name>` | `@reliva/web` |
| API routes | plural noun | `/api/tasks`, `/api/contexts` |
| MongoDB collections | plural noun | `tasks`, `contexts` |
| Environment variables | SCREAMING_SNAKE_CASE | `MONGODB_URI` |

## Running the Project

```bash
# Install all workspace dependencies (run from monorepo root)
bun install

# Start the web app in development
bun dev                          # delegates to apps/web via root scripts
# or directly:
bun run --cwd apps/web dev

# Build
bun build

# Typecheck
bun typecheck
```
